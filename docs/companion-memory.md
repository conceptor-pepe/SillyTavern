# 角色、背景与长期记忆

## 已实现

- 角色详情页可编辑完整资料、软删除角色。历史会话保留可读；已删除角色不能创建新会话或生成新回复。进行中的生成不会因角色删除而主动取消。
- Go Prompt 使用名称、描述、性格、场景、开场白、性别、年龄和示例对话；示例明确标为风格参考，不当作真实经历。
- 背景设置支持独立图片上传、开启/关闭、恢复使用角色封面。图片在浏览器压缩，服务器再次解码重编码；配置按账号保存到 MySQL。打开会话或刷新时读取最新配置，支持跨设备回读，暂非实时推送其他已打开的页面。
- 角色详情 → 记忆与世界书：可新增、修改、停用、删除长期事实或世界书。相同账号的同一角色在新会话中也能读取这些条目。条目不会自动从未经用户确认的剧情提取为跨会话事实。
- 世界书按最近四条消息中的关键词触发，支持常驻。长期事实支持关键词与可选向量相似度检索。
- 自动剧情摘要：从当前分支读取近期及更早祖先，按输入预算压缩旧消息；摘要只复用同一会话、同一祖先前缀、内容与角色快照散列完全匹配的缓存。修改源消息、角色设定或切换不同剧情后，旧摘要不能误用。

## API

- `PUT /api/v1/characters/:id`：完整替换可编辑角色资料；复用创建校验，保留旧角色卡未知扩展字段。
- `DELETE /api/v1/characters/:id`：软删除；归属不匹配或重复删除返回 404。
- `GET/PUT /api/v1/me/background`：`{ image, enabled }`。空图片使用当前角色封面。
- `GET/POST /api/v1/characters/:id/memories`。
- `PUT/DELETE /api/v1/characters/:id/memories/:memory`。
- 记忆请求字段：`kind: fact|lore`、`content`、`keywords: string[]`、`enabled`、`pinned`。用户编号与向量不能由客户端指定。记忆 ID 使用字符串。
- 正式装配的生成接口要求 `parent_id` 指向已保存的用户消息；不再走旧的“最早 100 条、混合分支”兼容路径。现有 Go 前端已符合要求。

## 配置

已有 JSON 配置加载时会继承环境变量默认值，新增字段不要求修改旧配置文件。

- `ContextBudget` / `AI_CHAT_CONTEXT_BUDGET`：默认 24000。输入使用 UTF-8 字节数加消息开销的保守估算，不是精确 tokenizer。应按实际模型上下文上限减去输出预留与安全余量配置。
- `OutputTokens` / `AI_CHAT_OUTPUT_TOKENS`：默认 2048，传入聊天供应商的 `max_tokens`。
- `EmbeddingURL` / `AI_CHAT_EMBEDDING_URL`：可选、完整 OpenAI 兼容 embeddings 地址。
- `EmbeddingKey` / `AI_CHAT_EMBEDDING_KEY`：可选服务密钥。
- `EmbeddingModel` / `AI_CHAT_EMBEDDING_MODEL`：向量模型名；URL 与模型需成对配置。

未配置 embedding 时仍可使用常驻记忆、关键词召回、世界书及自动摘要。配置后新建或重新保存条目会建立向量；切换向量模型后旧索引不会参与错误空间的比较，需要重新保存条目重建索引。供应商短暂失败时降级关键词，不把伪向量当成语义检索。

## 数据与边界

启动 AutoMigrate 新增 `backgrounds`、`memories`、`memory_summaries` 表，不重写旧消息、不执行旧系统数据实迁。

- 每角色最多 200 条记忆，每条最多 4000 UTF-8 字节；常驻条目合计含分隔开销不超过 6000 字节。世界书最多 16 个关键词。
- 背景 JPEG data URL 最大 350000 字符，解码最大 1024 × 1024；浏览器接收 JPG/PNG/WebP，最大原文件 5 MB。
- 摘要缓存持久化到 MySQL，Redis 不作为记忆真相来源。摘要按需同步生成，受 90 秒上下文准备时限控制；后续请求复用有效缓存。当前不是后台摘要队列。
- 历史回溯设置约 4000 条消息的扫描保护；达到上限明确失败，不宣称无限上下文。单条过长历史无法进入摘要或当前输入超预算时明确失败，不静默截断用户的问题。
- 用户维护的跨会话记忆与自动剧情摘要分离，避免模型把虚构情节、未选候选回复变成全局用户事实。
- 绑定长期角色的故事使用 `(user_id, companion_id)` 关系档案。关系阶段、现状和里程碑跨故事共享；关系记忆走 `/api/v1/relationships/:id/memories`，当前故事剧情仍走 `/api/v1/chats/:id/memories`。两层会在生成时同时召回，但不会把故事分支摘要提升为全局关系事实。
- “整理记忆”从当前选中分支生成带依据的候选。候选在用户确认前不会进入 Prompt；接受后按服务端确定的 relationship/story 范围写入，拒绝后同一会话不再重复建议。
- 删除记忆立即删除该条正文与向量，但不会删除对话原文或从对话原文重新得到的信息。删除角色保留历史；本轮没有增加角色恢复 UI。
- 旧 Node 世界书/向量索引/摘要的数据导入未执行；Go 新功能不依赖旧 Node 服务。
